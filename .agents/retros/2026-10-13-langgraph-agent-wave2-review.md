## 候选（按严重度）

### C10. 子代理结论被转写进 PR body 时未经二次核 · Coding standards（判断题，落文档）

- **事实**：本波五条评审发现里，**两条是实施侧自己的 body 写错，根因都是照抄子代理
  断言后没核**（实施侧自曝，原话「源头都是照抄子代理断言后没核」）——#127 body 写
  「`make_default_mock_client` 另有调用方（live_e2e.py、测试）」，实际直接调用方只有
  工厂本体与 `test_llm.py`，一次 grep 即证伪；#128 body 写 AC3 钉的是
  `state["compressed"] is True`，实码是弱析取，一次读测试即证伪。workflow.md 的
  `5e074f2` 纪律（禁改文档的子代理要另答「哪句声明失效了」）只覆盖了**子代理报告
  文档失效**这一半；主会话把子代理的**事实结论**（调用方名单、断言形态、门禁计数）
  转写进 body 时仍无核验要求。本次安全网全在评审侧（两条都被独立评审抓出），但网
  不应该只有一张。
- **修法方向**（判断题，最简档）：`5e074f2` 那条纪律或 code-review 自评审步骤加一句
  ——**body 里引用的每个数字/事实至少机械核一条再落笔**（调用方名单用 grep、断言形态
  用读测试、门禁计数用复跑）；转写子代理结论时先标「未核」直到核过。不值得上机械门
  （「引用是否核过」不可机检），是流程规则。

### C11. `gh run watch` 的收尾输出被截断，监视白做 · Tool economy

- **事实**：本会话四次用后台 `gh run watch … | Select-Object -Last 3` 盯 master CI，
  四次回来都是被截断的单行 + `.github#1` 重跑标记，分不清结论，每次都只得再跑一次
  `gh run list/view --json` 取终态——监视模式实际是「等通知 + 再查一遍」，多了一圈。
- **修法方向**（贴模式）：监视命令不接 `Select-Object`（或接全量输出）；收到完成通知
  后直接 `gh run list --branch master --limit 1 --json status,conclusion` + 需要时
  `gh run view <id> --json jobs`，一步到位。并入 C8 修法方向那份「pwsh 取证模式」。
