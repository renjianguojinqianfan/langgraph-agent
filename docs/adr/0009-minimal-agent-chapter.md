# 最简 agent 一章：pi 式工具面、计划文件、一条命令启动

> **本文是章节目标**：现役以 `AGENTS.md`「跨任务安全边界」表 + 代码为准，直到对应切片合并。
>
> 2026-10-18 – 10-19 用户拍板（一轮 grilling 逐条走完）。逐条结论、理由与被否选项见
> [决策日志](../capability-registry-rescope.md) §0（G-1 – G-35）；本文只记决策，不复制切片细节
> （切片见同文 §0.9，沿用 [ADR 0008](0008-single-loop-plan-build-modes.md) 的「文档分工」）。
> 对照物的一手调研：[pi](../research-pi-minimal-agent.md)、[dsh](../research-dsh-plugin-core.md)，
> 以及决策日志 §0.5 – §0.8 与 §0.6b（运行时部件、打包、计划形态、分发、计划与压缩）。

## 背景

转向（ADR 0008）之后，单 loop + 计划 / 执行两模式已经立住，但外围还挂着转向前一层层加上来的能力：
21 个内置工具（git ×7、知识库 ×2、OpenAPI、`code_exec`、`http_request`……）、产物账本、回滚快照、
辅助模型、工具重试与熔断、「重新规划」。起服务要两个进程；计划是一行行短句。

用户的目标是：**先做出一个相对稳定、最简、像 pi 一样一条命令就能启动的 agent**。
「心脏小」指**耦合小**——核不点名具体功能——而不是行数少（G-1）。可拆装的插件 + 预设是对的方向，
但推到下一章（G-6 / G-8），本章先把不该有的东西拿掉。

## 决策

1. **本章不做插件机制**。插件 + 预设（参照 dsh 的 profile / preset）留给以后那一章，#67 保留为它的占位票。
2. **工具面照 pi**：内置 read、write、edit、**bash**、ls、glob、grep、load_skill、web_search、spawn_subagent，外加 MCP。
   删除 `code_exec` / `http_request`（并入 bash）、git ×7（git 在 bash 里跑）、OpenAPI、知识库 ×2、插件目录自动加载与示例插件。
   ls / glob / grep / load_skill 留下，因为 bash 进不了计划模式与只读子代理，而 `read` 只能读工作区（G-9 / G-13 / G-18）。
3. **只读面**：计划模式与只读子代理 = read、ls、glob、grep、load_skill、web_search；子代理执行档 = 只读面 + write / edit，**不带 bash**（G-19）。
4. **bash 的安全口径照 D1 (b)**：危险规则默认空表、不附黑名单；bash 拿的是运行账号的权限，工作目录只是起点不是围墙，
   要隔离就放进容器或虚拟机——README 写清楚（G-23；[危险规则调研](../research-danger-policy-across-agents.md) §6.4）。
   子进程只放行环境变量白名单，密钥不进 bash。
   **修订（2026-10-20，M1 #172 / ADR 0010 决策 8）**：白名单照旧；但界面粘贴进 `~/.qianfan/credentials.json` 的 Key **bash 读得到**（同账号），这句话改为如实描述。
5. **只让本机访问**：监听 127.0.0.1，跨域只放行自身页面（G-20），Host 检查只认 127.0.0.1 / localhost（G-35）；
   `.env.example` 的 `HOST` 旁注一句「本章只支持本机访问」。**本章不支持远程访问**：远程模式（改监听 + 扩 Host 允许名单 + 必须开登录）整块不做（G-26）。
6. **交付 = 工作区里的文件**：「产物」栏换成「工作区文件」列表（整个工作区、不分任务、可预览下载，bash 写的也在）。
   删除产物账本与回滚快照；撤销改动靠 git（G-14）。
   **修订（2026-10-20，C5 #160 / ADR 0010 决策 6）**：范围改为**当前任务的目录**，并跳过 `.git` 与 `.gitignore` 忽略的文件；不再是「整个工作区、不分任务」。
7. **计划 = 一份 Markdown 文件**：计划模式仍严格只读；模型把计划写成 Markdown 放在回复里、用约定标记包住，
   **系统**把它存成工作区 `plans/<task_id>.md`（用任务 id 不用标题，避开非法字符与重名）；模型改计划时整份重写（G-27）。网页计划区显示整份 Markdown、可整份编辑，
   **修订（2026-10-20，C6 #161 / ADR 0010 决策 4）**：路径改为 `<任务目录>/.qianfan/plans/<task_id>.md`（首次创建写只含 `*` 的 `.gitignore`）；计划区显示**原文**（等宽、不排版），整份编辑写回文件。
   也可以用自己的编辑器改那个文件；不再追踪逐步的「待办 / 进行中 / 完成」（G-24 后续：第七轮推荐、用户未反对，第八轮切片表 C6 获「按表执行」，G-30）。
   计划文件被删时算「无计划」，执行模式下模型写计划文件也算计划更新、不拦（决策日志 §0.4）。
8. **计划交给执行阶段的方式**：计划以**一条消息**进入对话（不再钉在系统提示尾部），并带一句
   「以计划文件当前内容为准，与早先消息冲突时按计划做」（#153）。**每轮开始前（用户发新消息）与每次压缩之后**核对一次：
   文件与对话里那份不一致、或那份已被压缩挤掉，就删掉旧的那条、在末尾放最新一份——对话里始终只有一份计划；
   聊天界面只留一行「计划已更新到第 N 版」。任务跑着时改文件，下一条消息生效（G-29 / G-34；先例：Claude Code 压缩后从磁盘补计划，
   hermes 先删旧快照再补，见决策日志 §0.6b）。
9. **运行时部件**：留存档与停下 / 续说 / 续跑（含悬空调用清扫）、上下文注入、大结果驱逐、历史压缩、危险规则钩子、
   每轮步数上限、trace 文件、计划 / 执行两模式、登录（默认关）；删辅助模型、工具自动重试与熔断、「重新规划」（G-15 / G-21）。
10. **一条命令启动**：`qianfan` 是一个 Python 命令（`[project.scripts]`），本章用 `uv tool install -e .` 装给自己；
    后端同源托管打包好的 `frontend/dist` 并自动打开浏览器。**本章不分发**；分发放下一章，主渠道 PyPI + uv，npm / exe 以后按需套壳（G-22 / G-25）。
11. **界面原则**：看行为变化靠步骤视图就够，不做「每次调用的完整请求」视图；研究用也要把自己当用户，界面不杂乱（G-7）。

## 最简 agent 由什么组成（一页说明）

| 部件 | 是什么 | 现役落点 |
|---|---|---|
| 一条 loop | `agent → tool → agent`，一个 `agent` 节点；模式只换提示词与工具面；一轮没有工具调用即停下 | `backend/core/agent/graph.py`、`nodes.py` |
| 状态与存档 | `AgentState` + LangGraph checkpoint（续说 / 续跑）+ 任务记录 | `state.py`、`backend/services/task_manager.py`、`persistence.py` |
| 模型连接 | OpenAI 兼容客户端 + 离线模拟模型；**M1 起**多套配置（`data/models.json`）+ 凭据文件，按任务取客户端（ADR 0010 决策 7） | `backend/core/llm/` + `backend/services/model_store.py` |
| 工具 | 决策 2 的 10 个 + MCP；派发处按模式收窄工具面 | `backend/core/tools/`、`nodes.py::tool_node` |
| 危险规则钩子 | 设置里的规则表，命中即拒、把 `{block, reason}` 回给模型 | `backend/core/agent/policy.py` |
| 上下文 | 两层 AGENTS.md + 技能目录 + 环境信息注入；大结果驱逐；历史压缩 | `inject.py`、`context.py` |
| 事件 | EventBus → SSE（网页）+ trace 文件 | `backend/services/event_bus.py`、`trace.py`、`backend/api/sse.py` |
| 网页 | 步骤视图、计划文件、工作区文件 | `frontend/src/` |
| 启动 | `qianfan` → uvicorn（127.0.0.1）+ 托管前端 + 开浏览器 | 本章新增 |

核不点名具体功能（G-1 的尺子）这一条，本章只做到「删掉被点名的那些」；把剩下的接到统一卡口上是插件那一章的事。

## 三笔账（明说的代价）

1. **安全**：bash 等于把账号权限交给模型，没有沙箱、规则表默认不拦。这是 pi 的立场，不是遗漏；隔离靠容器。
2. **失去的能力**：回滚（改靠 git）、产物清单（换成工作区列表，不再分任务）、逐步状态、计划模式里看 git 状态、知识库、OpenAPI、远程访问。
3. **计划放在对话里**：比钉在系统提示里更符合主流做法，但要靠「每轮开始前 + 压缩之后核对、删旧补新」这条规则兜底；
   「文件改了就重发」这一半没有先例，是本仓为 #153 加的。

## 与 ADR 0008 的关系

**不动**：单 loop、计划 / 执行两模式（默认执行、黏性开关）、状态三值、「一轮的结束 = 没有工具调用」、危险钩子只 `{block, reason}`、
system prompt 每次调用重新生成（只是计划不再挂在它的尾部）。
