# 单一 loop + 计划/执行两模式，取代完成验证栈

> 2026-10-14 用户拍板（一轮 grilling 逐条走完，决策见下）。
> 参照物调研：[pi v1.2.0 的 agent 构建](../research-pi-agent-construction.md)。
> 落地方案（七片切法 + 每片判据）另文：[pivot-plan-build](../pivot-plan-build.md)——本文只记决策，
> 不复制执行细节（沿用 [ADR 0002](0002-moat-discipline-no-attention-reallocation.md) 的「文档分工（防漂移）」）。

## 背景

本仓库原有的信任模型是「**无人收尾**」：模型自己跑到终态，机器负责证明那个终态是真的。
完成验证栈（#46 两层 + 人工复核出口）、确认闸门、规划期风险扫描、无人值守评测入口
（`backend/headless.py` + PawBench 计分），全部是这一个前提的产物。

转向后的模型是「**人在两头**」：人先看/改/批计划，末尾看产物。**前提没了，不是东西做得太过**——
所以本次不是优化验证栈，而是把它连同前提一起撤掉。

## 决策

1. **一个任务 = 一段多轮对话**（同一条 `thread_id` / checkpoint）。任务常常一次做不完，模型缺信息
   还会反过来问，所以不是一问一答就结束。
2. **一条 loop**：只有一个 `agent` 节点。现存的 `planner` / `executor` 两节点合并；模式决定它拿到
   什么 prompt、什么工具面，**不是两个节点**。
3. **模式 = 任务上的一个开关**：**默认执行模式**（含任务的第一条消息）；用户**显式切过去**才走计划模式。
   开关是**黏的**（切到计划就一直计划，切回执行才回执行）。**不自动重新出计划**——计划做完了你再说一句，
   仍在执行模式。
4. **一轮的结束 = 这一轮没有工具调用**，球回到人手里。与 pi 的 loop 出口同形（实证见调研 §2）。
5. **状态机三值**：**跑着 / 停下（等你说话）/ 出错**。**没有「完成」这个终态**——「完成」就是「人不说了」。
   人按停的、进程崩的、模型答完的，在界面上都是同一个「停下」，都能接着跑。
6. **危险动作 = 设置里的规则表 + 一个钩子**：命中即**拒**，不执行，把 `{block, reason}` 当这次调用的
   结果回给模型；**不弹框、不进图重入**（模型看到拒绝自己换路）。
7. **工具面**：计划模式 = `explore` 档（12 个只读工具，复用 `subagent.py` 现有常量）；
   执行模式 = 全部已挂载工具，危险的那些交给第 6 条。`TOOL_TIERS` 不新增、不修改——**子 agent 保留**，
   仍在用它，计划模式天然拿不到 `spawn_subagent`。
8. **交付不是新状态**：就是停下时人去看产物。产物账本（[ADR 0004](0004-artifact-is-what-the-task-wrote.md)）
   的定义一字不改，只是它现在服务「交付视图」。

## 三笔账（明说的代价）

1. **项目身份重写**：`README.md` 第一段的「存在理由」不再成立（它卖的是"模型自称做完时被拦回来"），须重写。
2. **无人值守 / 评测分场景归零**：headless 与退出码语义消失，PawBench 计分面不再存在。这是**主动取舍**，
   不是遗漏——真模型验证改为「启服务、在网页端跑一遍」。参照物里 pi / opencode / codex 的公开 CI
   **都不跑真模型**（只有 dsh 的 `e2e.yml` 跑，且它自己掏这笔钱），所以删掉不等于离群。
3. **冻结区解除**：`resilience.py` / `registry.py` 的 CI 守卫与「`nodes.py` 的 `_needs_confirm`
   重算块不可动」的**文档级**约束，随闸门一并解除。**原约束无机械守卫（guard 不覆盖它），
   故那次删除动作由本文留痕**——这是 [ADR 0002](0002-moat-discipline-no-attention-reallocation.md)
   要求「触及决策本体的修正须先留痕」的那一类。

## 「停下」为什么落成任务状态（与 pi 的分歧，有意为之）

pi 的 loop 里**没有暂停态**：一轮结束就是「没有工具调用」（与本文第 4 条同形），而它那个
「停下等人」是**一个会阻塞的工具**（TUI 选项菜单；非交互态直接返回错误文本）。
本仓库选择把「停下」**落成任务状态**：我们要的是「任务可以在人不在时保持停下、进程重启后还在、
下一条消息接着跑」。pi 那种阻塞窗口只在常驻 TUI 里成立，在 Web + 任务模型里不成立。

## 与 pi 的有意分歧（调研实证 → 本仓库选择）

| 项 | pi v1.2.0 实证 | 本仓库选择 | 理由 |
|---|---|---|---|
| 钩子能力 | `{block?, reason?, terminate?}`，**可原地改参数、且改完不复核** | 只取 `{block, reason}`；**不改参数、不 terminate** | 「校验过的参数被钩子改掉且不复核」是后门，与本 ADR 第 6 条「当场拒」的极简立场也冲突；终止由人按停，不由策略层杀 |
| 模式的表达 | 没有 mode 对象：`setActiveTools(string[])` 就是模式；另设 `exposure`（可达性等级）与 `prepareLoadout`（编排类工具改写描述、隐藏部分声明） | 任务上一个开关即模式 | 那套是给「工具几十上百个、按需暴露」准备的；我们工具规模不到，学了是过度设计 |
| 计划进度 | 靠对模型回复**正则挖 `[DONE:n]`**，resume 重扫文本 + 一条锚点 | 结构化的 `Task.plan`（逐条状态、待在界面上直接编辑） | 结构化数据不必从文本里挖；可编辑也需要结构 |
| system prompt | 具名 section 表 + 后续以 section 补丁追加（`null` = 删） | 每次调用重新生成（`nodes._build_messages` 现做法） | 补丁式是为了跨 `/tree` 分支与 resume 存活；我们不做会话分支，不需要 |

## 重开条件

- 要重新引入**任何形式的「机器判定完成」**（哪怕是零成本的机械自检作为闸门），属本 ADR 重开，
  需要新拍板；理由不能只是"顺手"，得说清为什么人不再看那一眼。
- 要恢复**无人值守执行**（评测面、退出码语义、非交互驱动），属本 ADR 重开。
- 计划/执行的模式若要从「任务级开关」改成**每条消息显式选**，属本 ADR 第 3 条的重开。
