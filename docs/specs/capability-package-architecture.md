## 1. 目标与反目标

**目标**（用户四要求）：①能运行最小 agent ②可观测 ③可拆卸 ④加功能不改核心源码。
定位：本仓库的**下一章**（简历项目的架构升级），不是推倒重来；`mode="subtask"` 编译变体是既有先例。

**反目标**：把系统做小（极简主义已否决）；做成多租户企业平台；照抄 Deep Agents；为可拆卸牺牲闸门语义。

## 2. 三环模型

```
观测线（已成）：EventBus 订阅制——trace / #58 运行流水 / LLM 代理包装；总线永不为观测者改一行
    ▲ 装配（注册表代跑，TaskManager.__init__ 不再长 if 块）
能力包层（本设计要收口的部分）：每包 = 一个自描述模块
    ▲ 语义核（冻结区即边界）
语义核：planner → executor → tool → reflect + 闸门/熔断/完成验证/checkpoint-resume
```

**硬边界（最重要的决定）**：能力包**只能**贡献三样——工具、EventBus 订阅者、LLM 包装；
**不能**加图节点、不能碰闸门与验证语义。想改语义 = 过核心 PR + CI + ADR。
钩子点（pre_executor / post_tool / pre_finish）**暂不开放**——等第一个真实需求（防投机泛化）。

## 3. 能力包数据契约（强制，五声明）

每个能力包必须声明（文档表格形态，随包走的一页设计说明）：

| 声明项 | 内容 | 对应理解问题 |
|---|---|---|
| state 契约 | 读/写哪些 `AgentState` 键 | 「这一环传什么数据」 |
| 事件契约 | 发布/订阅哪些 EventBus 事件 | 「以什么形式传输」 |
| 工具契约 | 贡献哪些工具（含 schema、确认/韧性策略） | 「面上多了什么」 |
| settings 契约 | 拥有哪些配置键（77 键的收敛锚点） | 「怎么开关我」 |
| 件清单行 | #58 manifest 的自描述行 | 「装没装我一目了然」 |

不声明不能注册——不可拆解的包违背整条线的存在理由。#58 件清单从手写表改为注册表自描述驱动。

## 4. 最小核与 Profile

- `mode="minimal"`：字面 4 节点循环 `planner → executor → tool → reflect`（核心内一次性新增编译分支，不动 main）。
  拆解教学价值：全量图与最小图的差集 = 每个语义环节的增量（risk_scan 加上去图多了什么边——拓扑即课程）。
- 两级 profile（settings 预设叠加层，不是新开关体系）：
  - **bare**：零工具纯对话循环（最纯粹的拆解起点）
  - **minimal**：4 节点 + 只读三件 `read/glob/grep`（能干活、进 CI 断言）
- 前置依赖：`write` 独立工具落地（#56）+ file_io 退役（#17）——**两者均已合入**；剩「开关真摘面」一项，否则最小面定义不出来。

## 5. 迁移批次（存量 7 个内联块）

```
第一批：trace / manifest（最简单——当样板立验收模式）
第二批：KB / subagent
第三批：OpenAPI / Git
第四批：MCP（子进程生命周期，风险最高，殿后）
```

每批验收：离线全量绿 + ruff/mypy 0 错 + **件清单 diff 断言不变**（#58 当裁判）+ 冻结区零触碰。

## 6. 总验收判据

1. 装/卸一个能力包 → 件清单**恰好 ±1 行**，工具面同步消失
2. `agent_profile=minimal` → 清单 = 可断言的最短清单
3. 加一个功能 → `git diff` 零核心文件
4. bare → minimal → 全量，每级可运行、可回放（manifest + trace 双证据）
