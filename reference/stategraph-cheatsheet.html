StateGraph 核心概念速查

四要素

概念一句话项目落点官方 API
State共享黑板，节点间唯一的通信方式，用 TypedDict 声明AgentState（约 25 个字段）StateGraph(AgentState)
Node接收 state、干活、返回 state 更新的函数8 个节点方法挂在 AgentRuntime 上g.add_node(name, fn)
Edge固定路线，无条件必走全项目仅 1 条：finish → ENDg.add_edge(a, b) / set_entry_point
Conditional Edge路由函数读 state、返回下一节点名7 个出口全部是条件边g.add_conditional_edges(a, router)

最小可运行示例（背下来，面试白板用）

from langgraph.graph import StateGraph, END
from typing_extensions import TypedDict

class S(TypedDict):
    n: int

def step(s: S) -> dict:            # 节点：返回「更新」而非全量
    return {"n": s["n"] + 1}

def route(s: S) -> str:            # 路由：读 state，返回节点名
    return "step" if s["n"] < 3 else END

g = StateGraph(S)
g.add_node("step", step)
g.set_entry_point("step")
g.add_conditional_edges("step", route)

app = g.compile()                   # 可选：compile(checkpointer=...)
print(app.invoke({"n": 0}))        # {'n': 3}

main 拓扑 · 全图路由真值表

所有判断按顺序短路求值（与 graph.py 逐行对应）。这是本项目最重要的一张表。

出口节点路由顺序（命中即走）
plannerstop_requested → finish；否则 → risk_scan
risk_scanstop_requested → finish；否则 → subagent_split
subagent_splitstop_requested → finish；_last_action == "final_answer" → reflect；否则 → executor
executorstop_requested → finish；final_answer → reflect；_needs_confirm → human_confirm；否则 → tool
human_confirm恒 → tool（确认 = 放行，不是终点）
toolstop_requested → finish；_needs_confirm → human_confirm；否则 → reflect
reflectstop_requested → finish；final_answer → finish；step_index ≥ max_steps → finish；否则 → planner（循环！）
finish→ END（唯一的普通边）

设计规律：① stop_requested 在每个出口都是第一优先级——宁可少做，不可失控； ② 防失控有三道独立保险：stop_requested（人）→ max_steps（预算）→ LangGraph recursion_limit（框架兜底）。

术语表

术语定义
State图共享的状态对象；节点靠它通信
Node改变状态的函数
Edge / Router固定边 / 条件边的路由函数
Entry Point图的入口节点（本项目：planner）
END终结标记，走到即停止
Superstep （课程 02）一轮「执行若干节点 + 广播状态更新」的批次单位；副本语义的根源
Reducer （课程 02）声明某字段如何合并更新（如 operator.add 追加）
Checkpointer （课程 04）每 superstep 落盘一次状态的持久化后端（项目用 SqliteSaver）
Thread （课程 04）一个 checkpointer 下的会话线程，thread_id 定位（项目里 = task_id）
Interrupt （课程 03）官方 human-in-the-loop 原语：节点内暂停图执行、持久化、等人
