# Quality-gate toolchain (ruff/mypy match the CI backend-test job; pre-commit is
# only the local git-hook framework -- CI never runs hooks, the pin exists for
# reproducible local runs).
#
# ASCII-only on purpose: Windows pip reads requirements by locale; keep ASCII
# so cp936 does not fail (#259).
#
# Why not merge into requirements.txt: runtime installs only requirements.txt
# and does not need linters; merging would add two extra tools to the qianfan
# tool environment.
#
# Why exact pins instead of ranges: ruff/mypy rule sets and defaults drift on
# their own -- a minor bump can turn CI red with ZERO code changes (new rules,
# new default selects, new type inference). Same rationale as the three pinned
# langgraph packages in requirements.txt: the gate's judge must be stable;
# upgrades go through human evaluation (run locally, clear new violations,
# then change this file).
#
# Local usage:
#   .venv314\Scripts\python.exe -m pip install -r requirements-dev.txt
#   .venv314\Scripts\python.exe -m ruff check backend scripts start.py
#   .venv314\Scripts\python.exe -m mypy
ruff==0.16.7
mypy==2.3.1
pre-commit==4.6.2   # commit-time hook framework: config in .pre-commit-config.yaml (including the
                    # commit-msg hook); hook content always language: system invoking .venv314,
                    # with zero second version source
