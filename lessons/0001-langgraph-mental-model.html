LangGraph 心智模型：你的项目就是一张图

为什么学这个：面试的第一个问题永远是「讲讲你的项目」。讲清这个项目的第一步， 是讲清它的骨架——一张 LangGraph 状态图。这节课结束时，你要能看懂、画出、并讲出 你项目里那张图。

一、为什么需要 LangGraph

先想一个朴素的问题：让大模型自主完成多步任务，最直接的写法是什么？一个 while 循环—— 每轮把当前情况喂给大模型，让它决定「调用哪个工具」或「这一轮结束」，执行后继续循环，直到结束。

这样写能跑，但控制流藏死在代码里：想在中间插入「停止」并保证下一轮能从同一个 checkpoint 接着跑？想限制一轮最多走多少步？想按模式换 prompt 和工具面？改循环体，而且越改越乱。 循环一复杂，没人能一眼说清「程序现在可能处于哪些状态」。

LangGraph 的选择是：把控制流显式建模成一张图。步骤是节点，走向是边， 共享数据是一个状态对象。图是声明式的——哪些路线存在一目了然；图是可执行——框架负责沿边调度； 图还是可持久化的锚点——断点续跑正是靠「图 + 检查点」实现的。

LangGraph 是一个用于构建 Agent 的底层编排框架（low-level orchestration framework）， 以可控和可持久化为核心卖点：你可以精确定义控制流，也可以随时中断、恢复。 —— 摘译自 LangGraph 官方文档 · Graph API

二、StateGraph 四要素

下面每个概念都配你项目里的真实代码。这不是教学玩具——你现在读的就是简历上那个项目的骨架。

要素 1 · State：一块共享黑板

整张图共享一个状态对象，类型用 TypedDict 声明。它是所有节点的唯一通信方式—— 节点之间不互相调用，只通过读写这块黑板协作。

# backend/core/agent/state.py（节选）
class AgentState(TypedDict, total=False):
    """Mutable state passed between graph nodes."""
    task_id: str
    mode: str                        # plan | build（任务上的黏性开关）
    messages: List[Dict[str, Any]]   # 对话历史（OpenAI 风格）
    plan: List[Dict[str, Any]]       # 当前计划（PlanStep 列表）
    step_index: int                  # 整个任务内的累计步号
    round_steps: int                 # 本轮已用步数（预算）
    stop_requested: bool             # 用户点了「停止」？
    final_answer: str
📄 完整定义见 backend/core/agent/state.py（建议现在通读一遍，5 分钟）

要素 2 · Node：改状态的函数

每个节点就是一个函数：接收当前 state，干活（通常调一次大模型或执行工具），返回对 state 的更新。 你的项目只有 3 个节点：唯一的 LLM 节点 agent、执行工具的 tool、 收尾停下的 finish。计划 / 执行两种模式不是两个节点，而是 agent 内部换 prompt 和工具面（ADR 0008 决策 2）。

# backend/core/agent/graph.py（节选）
g = StateGraph(AgentState)
g.add_node("agent",  runtime.agent)      # 唯一的 LLM 节点
g.add_node("tool",   runtime.tool_node)  # 真正执行工具
g.add_node("finish", runtime.finish)     # 收尾：停下（INTERRUPTED）或 FAILED
g.add_edge(START, "agent")               # 入口

要素 3 · Edge：固定路线

确定无疑的走向用普通边。项目里有两条：START → agent 和 finish → END——收尾节点之后必然结束。

要素 4 · Conditional Edge：路由函数（精髓所在）

有分支的走向用条件边：注册一个路由函数，它读当前 state，返回下一个节点的名字。 循环、停下、异常退出，全靠它。

# backend/core/agent/graph.py — 两个真实路由
def _after_agent(s: AgentState) -> Literal["finish", "tool"]:
    if s.get("stop_requested") or s.get("error"):
        return "finish"
    if s.get("_last_action") == "final_answer":
        return "finish"          # 本轮最后一次调用没有 tool call
    return "tool"

def _after_tool(s: AgentState) -> Literal["finish", "agent"]:
    if s.get("stop_requested"):
        return "finish"
    if s.get("round_steps", 0) >= runtime.max_steps:
        return "finish"          # 本轮步数用尽
    return "agent"
面试视角：这两个路由函数就是「agent 的决策不是 if-else 写死、而是大模型现场决定」与 「工程约束（停止、预算、错误）由确定性代码强制执行」的分界线——大模型决定想做什么， 路由函数决定允许走哪条路。记住这句话，第 11 课的追问题库会用到。

三、把整张图画出来

把 3 个节点和条件边拼起来，就是你项目的 main 拓扑—— 整个项目唯一的一张图，全部写在 graph.py 里：

怎么读这张图：从 START 进入 agent。它要么返回 tool call（去 tool， 执行完再回 agent），要么返回文字（这一轮结束，去 finish）。 这个大回环就是「自主 Agent」的本体：决定、执行、观察、再决定，直到模型不再调工具， 或人叫停、或本轮步数用尽。停下来不是「完成」——任务变成 INTERRUPTED，人看产物、 再决定是否续说。

五、检索练习（本课作业）

练习 1 · 画图：拿一张纸，画出 main 拓扑：3 个节点 + START / END， 并给每条分支箭头标注判断条件。

画完后再展开对照 以上面的 SVG 图为准。自查三问：① tool 回到 agent 的箭头画了吗（很多人漏掉循环边）？ ② agent 什么时候去 finish？（本轮最后一次调用没有 tool call / stop / error） ③ stop 和步数用尽为什么也去 finish？

练习 2 · 路由顺序：不看代码，说出 _after_agent 和 _after_tool 的完整判断顺序。

展开答案 _after_agent：① stop / error → finish；② 本轮最后一次调用没有 tool call → finish； ③ 否则 → tool。
_after_tool：① stop → finish；② round_steps ≥ max_steps → finish； ③ 否则 → agent。顺序本身也有含义：停止优先级最高，预算其次。

六、面试弹药：60 秒项目讲述（v1）

「这是一个基于 LangGraph 的自主任务 Agent 平台。用户给一句自然语言任务， 后端用 StateGraph 编排一条 agent → tool → agent 的循环：一个 LLM 节点按任务的 plan / build 模式换 prompt 和工具面，工具调用回到同一个 agent，直到本轮最后一次调用不再调工具， 任务停下、人看产物；停下后可以沿同一 checkpoint 续说。 危险动作由设置里的规则表 + 一个钩子当场拒，不弹确认框。 整个执行过程通过 SSE 实时推送到前端可视化。」

面试官内心戏：这段话只回答了「是什么」，最多换来 30 秒兴趣。他接下来必然追问 「为什么这么设计」「遇到过什么坑」——那需要真正的机制理解，是课程 10–11 的内容。 现在的你先做到一件事：这 60 秒里的每个名词，你都知道它对应图上的哪个节点。
