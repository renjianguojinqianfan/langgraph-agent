LangGraph 心智模型：你的项目就是一张图

为什么学这个：面试的第一个问题永远是「讲讲你的项目」。讲清这个项目的第一步， 是讲清它的骨架——一张 LangGraph 状态图。这节课结束时，你要能看懂、画出、并讲出 你项目里那张图。

一、为什么需要 LangGraph

先想一个朴素的问题：让大模型自主完成多步任务，最直接的写法是什么？一个 while 循环—— 每轮把当前情况喂给大模型，让它决定「调用哪个工具」或「任务完成」，执行后继续循环，直到结束。

这样写能跑，但控制流藏死在代码里：想在中间插一道「高危操作先问人」的闸门？ 改循环体。想在任意一步支持「停止」并且之后从断点恢复？改循环体，而且越改越乱。 循环一复杂，没人能一眼说清「程序现在可能处于哪些状态」。

LangGraph 的选择是：把控制流显式建模成一张图。步骤是节点，走向是边， 共享数据是一个状态对象。图是声明式的——哪些路线存在一目了然；图是可执行——框架负责沿边调度； 图还是可持久化的锚点——后面课程会看到，断点续跑正是靠「图 + 检查点」实现的。

LangGraph 是一个用于构建 Agent 的底层编排框架（low-level orchestration framework）， 以可控和可持久化为核心卖点：你可以精确定义控制流，也可以随时中断、恢复。 —— 摘译自 LangGraph 官方文档 · Graph API

二、StateGraph 四要素

下面每个概念都配你项目里的真实代码。这不是教学玩具——你现在读的就是简历上那个项目的骨架。

要素 1 · State：一块共享黑板

整张图共享一个状态对象，类型用 TypedDict 声明。它是所有节点的唯一通信方式——节点之间不互相调用，只通过读写这块黑板协作。

# backend/core/agent/state.py（节选）
class AgentState(TypedDict, total=False):
    """Mutable state passed between graph nodes."""
    task_id: str
    messages: List[Dict[str, Any]]   # 对话历史（OpenAI 风格）
    plan: List[Dict[str, Any]]       # planner 产出的计划
    step_index: int                  # 循环计数
    stop_requested: bool             # 用户点了「停止」？
    _needs_confirm: bool             # 本轮动作需要人工确认？
    final_answer: str
📄 完整定义见 backend/core/agent/state.py（约 50 行，建议现在通读一遍，5 分钟）

要素 2 · Node：改状态的函数

每个节点就是一个函数：接收当前 state，干活（通常调一次大模型或执行工具），返回对 state 的更新。你的项目有 8 个节点：循环主体 planner / executor / tool / reflect，加 risk_scan / subagent_split / human_confirm / finish。

# backend/core/agent/graph.py（节选）
g = StateGraph(AgentState)
g.add_node("planner",  runtime.planner)   # 拆解计划
g.add_node("executor", runtime.executor)  # 决定下一步动作
g.add_node("tool",     runtime.tool_node)  # 真正执行工具
g.add_node("reflect",  runtime.reflect)   # 反思、决定继续与否
g.set_entry_point("planner")              # 入口

要素 3 · Edge：固定路线

确定无疑的走向用普通边。整个项目只有一条：g.add_edge("finish", END)——收尾节点之后必然结束。

要素 4 · Conditional Edge：路由函数（精髓所在）

有分支的走向用条件边：注册一个路由函数，它读当前 state，返回下一个节点的名字。循环、闸门、异常退出，全靠它。

# backend/core/agent/graph.py — executor 之后的路由（真实代码）
def _after_executor(s: AgentState) -> str:
    if s.get("stop_requested"):
        return "finish"          # 用户叫停 → 收尾
    if s.get("_last_action") == "final_answer":
        return "reflect"         # 模型宣布完成 → 去反思
    if s.get("_needs_confirm"):
        return "human_confirm"   # 高危动作 → 先过闸门
    return "tool"                # 默认 → 执行工具

g.add_conditional_edges("executor", _after_executor)
面试视角：这个 4 行路由函数就是「agent 的决策不是 if-else 写死、而是大模型现场决定」与 「工程约束（停止、确认、预算上限）由确定性代码强制执行」的分界线——大模型决定想做什么， 路由函数决定允许走哪条路。记住这句话，第 11 课的追问题库会用到。

三、把整张图画出来

把 8 个节点和所有条件边拼起来，就是你项目的 main 拓扑——整个项目唯一的一张图，全部写在 graph.py 的 110 行里：

怎么读这张图：从 start 进入 planner，沿着蓝色主路径顺时针走 planner → risk_scan → subagent_split → executor → tool → reflect，然后回到 planner—— 这个大回环就是「自主 Agent」的本体：规划、执行、观察、反思，再规划，直到模型给出最终答案或触发上限。 每个节点出口处的分支由路由函数决定，判断条件就标在箭头旁边。
